How we keep circles safe from inappropriate video

A simple guide to how Greetup checks video during a call — on your phone or computer — and what happens if something is not allowed.

💡 What is this?

When someone joins a live circle (group video call) with their camera on, our app quietly looks at their own video from time to time — only on their device.

We use a small AI model called nsfwjs to guess if the picture looks inappropriate. If it does, we remove only that person from the call. Other people can keep talking.

Important: We do not send video or screenshots to our servers. The check happens on the user's device. The server only gets a small “something went wrong” message with scores — not the image.

🎯 Big idea in one sentence

Your phone checks your own camera → if it’s sure something is wrong twice in a row → it tells the server → the server kicks you and saves a record.

👣 Step by step (while you are in a call)

  1. You join a circle with camera on The safety check only runs when your camera is on — not for screen share.
  2. Every 12 seconds, we take one tiny snapshot Think of it like a single photo frame, drawn on your device into a small square (224×224 pixels). Nobody else sees this snapshot.
  3. The AI gives scores It labels the frame things like “Neutral”, “Porn”, “Sexy”, etc., each with a number from 0 to 1 (how sure it is).
  4. We compare scores to our rules For example: “Porn” or “Hentai” above 70% counts as bad. “Sexy” needs to be above 85% (stricter, fewer mistakes).
  5. We need two bad results in a row One bad frame might be a mistake (bad lighting, beach photo, etc.). So we only act after two checks in a row say it’s bad (~24 seconds apart).
  6. Your app tells our server It sends: which room you were in + the score numbers. Still no image.
  7. The server removes you from that circle only You get kicked from the call. You cannot rejoin that same circle. Everyone else stays in the call.
  8. We save one row in the database Table: nsfw_moderation_events — who, which room, when, what action we took, and the scores (for support / appeals later).

🔄 Picture of the flow

Your device → Camera frame every 12s
nsfwjs on device → Scores (no upload)
2 bad checks? → POST /room/…/nsfw-violation
Server → Kick you + save event
Database + Socket message to your app

⚖️ What happens to the user?

First time (strike 1)

Removed from the circle. A warning message explains this was inappropriate video. This is your only warning — counted for 90 days.

Second time (strike 2)

Removed again, and your account is banned (is_banned = yes). You cannot use the app like a normal user until an admin fixes it.

Strikes older than 90 days do not count toward that “second time” rule anymore.

🗄️ What we store (database)

We use a table called nsfw_moderation_events — one row per incident:

Field Meaning (simple)
user_idWho broke the rule
room_idWhich circle call
sourceRight now: live_circle_self (their own video)
strike_index1st, 2nd strike in the last 90 days
action_takenWarned + kicked, or account banned
client_scoresAI numbers only — not a photo
overturnedFor future appeals (if we undo a strike)

The users table only keeps is_banned (yes / no / temporarily) for login and search — not a strike counter column.

🛡️ Privacy & safety notes

  • Video stays on the device during the check.
  • We only scan your own camera — not screen share (saves load; fewer false alarms).
  • Checks pause when the browser tab is hidden.
  • Checks stop when the camera is off.
  • The server decides the kick and ban — the client only reports “I failed the check.”

📁 Where is the code?

  • Client scanner: client/src/features/moderation/
  • Hook in call UI: InCallContainer → useCircleNsfwModeration
  • Server API: POST /api/room/:roomId/nsfw-violation
  • Server logic: report-circle-nsfw-violation.service.ts
  • Schema: server/src/core/database/schema/moderation.ts
